1 Tổng quan dự án

1.1. Dự án này làm gì?

Đây là một chương trình nhận diện cảm xúc trên khuôn mặt người theo thời gian thực. Bạn mở webcam lên, chương trình sẽ:

  1. Phát hiện khuôn mặt trong khung hình (dùng Haar Cascade).
  2. Cắt riêng từng khuôn mặt ra.
  3. Đưa qua mô hình AI (EfficientNet đã được huấn luyện trên hàng trăm nghìn ảnh) để dự đoán cảm xúc.
  4. Hiển thị kết quả ngay trên màn hình: khung màu quanh mặt + tên cảm xúc + độ tin cậy.

Ngoài chế độ webcam, chương trình còn có thể nhận diện từ ảnh tĩnh, file video, fine-tune model, và đánh giá kết quả.

Khi bạn gõ python main.py --mode webcam, file này là file đầu tiên được chạy. Nó làm 3 việc:

  1. Đọc tham số từ dòng lệnh.
  2. Dựa vào chế độ, gọi hàm xử lý tương ứng.
  3. Bắt lỗi nếu có.
main.py main() dòng 482

Công việc: Gọi build_parser() → đọc tham số → dùng dispatch dict để gọi đúng hàm theo mode.

Dispatch pattern: { 'webcam': run_webcam, 'image': run_image, ... } — thay vì 5 câu if/else, dùng dict cho gọn.

main.py run_webcam(args) dòng 37

Luồng chạy:

  • Mở camera → vòng lặp while True đọc frame.
  • Frame chẵn (mỗi 2 frame): chạy AI → vẽ kết quả mới.
  • Frame lẻ (skip): vẽ lại kết quả cũ — tiết kiệm CPU, không giật hình.
  • Xử lý phím: q/ESC thoát, s chụp ảnh, r reset buffer.

engine.process_frame(frame) — lệnh quan trọng nhất: detect mặt + predict emotion.

4.2 src/constants.py — Hằng số dùng chung

constants.py

Chứa 4 nhóm hằng số:

  • EMOTION_COLORS — Màu BGR cho từng emotion, dùng khi vẽ khung.
  • EMOTION_DISPLAY_MAP — Map tên model → tên hiển thị thân thiện. VD: 'Anger'→'Angry', 'Happiness'→'Happy', 'Contempt'→'Disgust'.

4.4 src/emotion_engine.py — Engine nhận diện cảm xúc

Vai trò: "Trái tim" của hệ thống — chứa toàn bộ logic AI phát hiện mặt và nhận diện cảm xúc.

emotion_engine.py EmotionEngine.__init__() dòng 22

Khi tạo EmotionEngine, 4 việc xảy ra:

  1. Khởi tạo HSEmotionRecognizer — tải model EfficientNet (~20-30MB) vào bộ nhớ.
  2. Tải Haar Cascade — bộ phát hiện khuôn mặt cổ điển (nhanh, chạy CPU).
  3. Load fine-tuned weights (nếu có) — nạp trọng số đã huấn luyện thêm.
  4. Khởi tạo 3 kỹ thuật nâng cao:
    • Temporal Smoothing: Buffer 10 frame/khuôn mặt → lấy trung bình → mượt.
    • Adaptive Thresholds: Ngưỡng riêng: Happiness ≥ 50%, Sadness ≥ 30%, ...
    • CLAHE: Cân bằng sáng cục bộ → rõ nét hơn khi thiếu sáng.
emotion_engine.py predict_emotion(face_img, face_key) dòng 114

Quy trình đầy đủ:

  1. Tiền xử lý ảnh mặt: _preprocess_face (BGR→Gray→CLAHE→RGB).
  2. Gọi HSEmotionRecognizer → ra 8 xác suất (softmax).
  3. Temporal Smoothing: Lưu scores vào buffer → tính trung bình 10 frame.
  4. Lấy emotion có điểm cao nhất (argmax).
  5. Adaptive Threshold: Nếu điểm < ngưỡng → Neutral. Ngược lại → emotion đã map tên.

Trả về: (emotion, confidence, prob_vector) — ví dụ: ("Happy", 0.85, [0.02, ...])

emotion_engine.py detect_faces(frame) / process_frame(frame) dòng 157 / 165

detect_faces: Chuyển ảnh sang xám → Haar Cascade → trả về list [(x,y,w,h), ...].

process_frame: Hàm tổng hợp: gọi detect → dọn buffer cũ → với mỗi mặt ≥48px, gọi predict_emotion → trả về list kết quả.

Tham số Haar: scaleFactor=1.1 (quét 10% mỗi lần), minNeighbors=5 (giảm false positive).

4.6 src/file_tuner.py — Fine-tune model

Fine-tune là gì? Hãy tưởng tượng model AI như một đầu bếp đã học trường danh tiếng (450,000 ảnh). Bạn muốn đầu bếp này nấu theo phong cách gia đình bạn (dataset của bạn). Fine-tune là: giữ kỹ năng cơ bản (backbone), chỉ điều chỉnh cách "trang trí" (classifier).
file_tuner.py EmotionFineTuner

Chiến lược:

  • Đóng băng toàn bộ backbone — giữ đặc trưng học từ 450k ảnh.
  • Mở 2 blocks cuối + classifier — chỉ ~5% tham số được học tiếp.
  • Lý do: Dataset riêng chỉ 140-350 ảnh — nếu mở toàn bộ sẽ overfit ngay.

_load_model() — static method tải model từ file .pt cache, sửa lỗi tương thích key classifier.0.weight → classifier.weight.

file_tuner.py load_dataset() / train()

load_dataset: Đọc cấu trúc thư mục → map tên lớp → chia 70/15/15 → tạo DataLoader.

train: Với mỗi epoch:

  • Train: nạp batch → forward → tính loss → backward → update weights.
  • Validation: nạp batch → tính loss + accuracy (không update).
  • Lưu model nếu val accuracy tốt hơn (best model).

4.7 src/evaluator.py — Đánh giá model

evaluator.py ModelEvaluator

So sánh model gốc và fine-tuned trên test set:

  • evaluate_and_compare() — Tính accuracy, in classification report.
  • _plot_confusion_matrix() — Bảng N×N: hàng=nhãn thật, cột=nhãn dự đoán.
  • _plot_training_curve() — Biểu đồ loss + accuracy theo epoch.

Confusion matrix: Đường chéo = đúng, ngoài đường chéo = sai. Giúp biết lớp nào model yếu.

5 Giải thích các khái niệm chuyên môn

Haar Cascade

Thuật toán phát hiện vật thể cổ điển (Viola-Jones 2001). Quét cửa sổ nhỏ qua ảnh, so sánh tổng pixel giữa các vùng. Ví dụ: vùng mắt tối hơn vùng trán → 1 đặc trưng. Nếu đủ nhiều đặc trưng khớp → đó là khuôn mặt.

Ưu: rất nhanh, chạy CPU. Nhược: kém với mặt nghiêng/thiếu sáng.

BGR vs RGB — OpenCV

OpenCV đọc ảnh theo BGR (Blue-Green-Red), khác RGB thông thường. Cần chuyển đổi khi dùng matplotlib: cv2.cvtColor(img, cv2.COLOR_BGR2RGB).

EfficientNet

Kiến trúc neural network do Google phát triển (2019). Cân bằng 3 chiều: độ sâu, độ rộng, độ phân giải → chính xác tối đa với ít tham số nhất. Code dùng phiên bản B0 (nhẹ nhất) với 8 lớp output.

Softmax & Argmax

Softmax: Biến mảng số thành xác suất (tổng = 1). Công thức: softmax(xi) = exp(xi) / sum(exp(xj)).

Argmax: Lấy chỉ số phần tử lớn nhất. argmax([0.02, 0.85, 0.03]) = 1.

Temporal Smoothing

Dùng deque lưu 10 kết quả gần nhất, mỗi frame lấy trung bình. Tác dụng: (1) bù cho frame bị nhiễu, (2) cảm xúc thay đổi từ từ, smoothing phản ánh đúng bản chất.

CLAHE

Contrast Limited Adaptive Histogram Equalization — cân bằng sáng cục bộ. Chia ảnh thành ô nhỏ, cân bằng từng ô riêng, có giới hạn tương phản → nổi chi tiết, tránh nhiễu.

CrossEntropyLoss

Hàm mất mát cho phân loại nhiều lớp. Loss = -log(softmax_score[của lớp đúng]). Nếu model đoán đúng 95% → loss ≈ 0.05. Nếu sai → loss cao.

Learning Rate & Epoch

Epoch: 1 lần quét hết dataset. Learning Rate: kích thước bước cập nhật trọng số. Mặc định 1e-4 (0.0001) — phù hợp fine-tune.

Overfitting (Quá khớp)

Model "học thuộc" dữ liệu train, không khái quát hoá được. Dấu hiệu: train acc 98%, val acc 60%.

Code chống: (1) đóng băng backbone, (2) validation mỗi epoch, (3) chỉ lưu best model.

6 Câu hỏi bảo vệ và câu trả lời gợi ý

1 Tại sao dùng HSEmotion mà không tự train từ đầu? ▼
Training EfficientNet từ đầu cần hàng trăm nghìn ảnh và nhiều ngày trên GPU mạnh. HSEmotion đã train sẵn trên AffectNet (450,000 ảnh). Mình chỉ cần fine-tune trên dataset nhỏ (140 ảnh) — vừa nhanh (vài phút), vừa tận dụng được kiến thức từ tập dữ liệu lớn (transfer learning).
2 Haar Cascade — ưu nhược điểm? Có thể thay bằng gì? ▼
Haar Cascade nhanh (real-time trên CPU), nhưng kém với mặt nghiêng, bị che, thiếu sáng. Có thể thay bằng MTCNN (chính xác hơn, chậm hơn) hoặc YOLOv8-face (cần GPU).
3 Temporal Smoothing hoạt động thế nào? ▼
Mỗi khuôn mặt có buffer lưu 10 kết quả gần nhất (dùng deque). Kết quả cuối = trung bình 10 frame. Giúp tránh nhảy loạn emotion do ảnh bị nhiễu hoặc face bị mờ tạm thời.
4 Tại sao mỗi emotion có ngưỡng riêng (Adaptive Threshold)? ▼
Happiness thường được dự đoán với độ tin cậy cao (≥80%), ngưỡng 0.50 an toàn. Sadness và Surprise dễ bị nhầm, điểm thấp hơn — hạ ngưỡng xuống 0.30-0.35 để không bỏ sót. Nếu không đạt ngưỡng → trả về Neutral (an toàn nhất).
5 Dataset gồm những emotion nào? Số lượng? ▼
7 lớp: Anger, Disgust, Fear, Happiness, Neutral, Sadness, Surprise. Mỗi lớp 20 ảnh → tổng 140 ảnh. Ảnh được sưu tầm từ nhiều nguồn (Kaggle, Google Images).
6 Quá trình fine-tune chia dữ liệu thế nào? ▼
Chia 70% train (~98 ảnh), 15% val (~21 ảnh), 15% test (~21 ảnh). Chia ngẫu nhiên với seed cố định 42 để kết quả tái lập được.
7 Tại sao đóng băng backbone, chỉ mở 2 blocks cuối? ▼
Backbone đã học đặc trưng tổng quát từ 450k ảnh. Dataset riêng quá nhỏ (98 ảnh train) — nếu mở toàn bộ sẽ overfit ngay. Chỉ mở 2 blocks cuối (~5% tham số) để tinh chỉnh riêng cho dataset của mình.
8 Dấu hiệu overfit? Code xử lý gì để chống? ▼
Dấu hiệu: train acc cao nhưng val acc thấp. Code chống bằng: (1) đóng băng backbone, (2) validation mỗi epoch, (3) chỉ lưu model khi val accuracy tốt nhất (best model), không lưu model cuối.
9 Confusion matrix và classification report cho biết gì? ▼
CM là bảng N×N: hàng=nhãn thật, cột=nhãn dự đoán. Đường chéo = đúng, ngoài = sai. Classification report gồm precision, recall, F1 cho từng lớp — biết lớp nào model yếu nhất.
10 Nếu muốn cải thiện độ chính xác, sẽ làm gì? ▼
(1) Tăng dataset, nhất là các lớp model yếu. (2) Thay Haar bằng MTCNN/YOLO. (3) Tăng epoch hoặc giảm lr. (4) Dùng EfficientNet-B2 (lớn hơn B0). (5) Thêm data augmentation (xoay, lật, thay đổi độ sáng).
11 skip_frames hoạt động thế nào? ▼
skip_frames = 2 → chỉ xử lý AI trên frame chẵn. Frame lẻ vẽ lại kết quả cũ. Webcam 30 FPS, AI ~15 FPS → kỹ thuật này cho hình mượt (30 FPS) mà AI vẫn kịp.
12 File .pt là gì? Bên trong chứa gì? ▼
.pt là checkpoint PyTorch. Chứa: model_state_dict (trọng số), class_names, model_name, val_acc (accuracy tốt nhất), epoch.
13 _get_face_key làm gì? Ý nghĩa lưới 60px? ▼
Tạo mã định danh cho khuôn mặt từ toạ độ tâm, lượng tử hoá vào lưới 60px. Nếu mặt rung < 60px — key không đổi → cùng buffer → kết quả mượt. Tránh tạo buffer mới liên tục khi mặt không di chuyển nhiều.
14 Tại sao BGR→Gray→RGB trong tiền xử lý? ▼
OpenCV đọc ảnh BGR. Chuyển Gray (1 kênh) để CLAHE xử lý — CLAHE chỉ hoạt động với ảnh xám. Sau đó chuyển lại RGB (3 kênh) vì HSEmotion yêu cầu đầu vào 3 kênh màu.
15 Kiến trúc tổng thể của hệ thống? ▼
Gồm 3 khối: (1) Input — webcam/image/video. (2) Xử lý — EmotionEngine (Haar Cascade detect + HSEmotion predict + smoothing + threshold). (3) Output — overlay hiển thị, có thể lưu ảnh/video. Fine-tune/evaluate hoạt động riêng với luồng chính.
